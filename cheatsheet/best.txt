# best practices - cara bener ngurus server biar gak meledak

1. USER & PERMISSION - JANGAN PAKAI ROOT BUAT HARIAN
- Selalu pakai user biasa + sudo, bukan root langsung. root cuma buat install awal
- adduser bukan useradd (di Ubuntu). Selalu adduser --disabled-password buat service user
- mantra sakti: usermod -aG (jangan lupa -a, kalau lupa group lama hilang!)
- File service: chown ershad:www-data, chmod 775 folder, 664 file, 600 buat .env & ssh key
- JANGAN PERNAH chmod 777 buat benerin error, itu nutupin masalah. Cek: ls -l + namei -l /var/www/app/.env
- Folder project bareng: chmod g+s + setfacl -R -m d:g:www-data:rwx biar file baru otomatis group bener
- SSH: chmod 700 ~/.ssh, 600 authorized_keys & id_rsa, PasswordAuthentication no di /etc/ssh/sshd_config

2. SYSTEMD - BIAR APP GAK MATI PAS REBOOT
- Urutan sakti: edit file -> daemon-reload -> enable --now -> status -> journalctl -f
- Selalu pakai enable --now, bukan start doang. Start doang = pas reboot lupa gak jalan
- Pakai Restart=always + RestartSec=3 buat app, Restart=on-failure buat worker yang error config
- Jangan tulis password di service file, pakai EnvironmentFile=/home/ershad/app/.env
- Limit resource: MemoryMax=500M CPUQuota=80% biar 1 app gak makan server
- File service kamu taruh di /etc/systemd/system/, jangan di /lib/systemd/system/ (itu punya apt)
- Cek boot lama: systemd-analyze blame | head -n 20

3. NGINX - REVERSE PROXY & JANGAN EDIT LANGSUNG DI ENABLED
- Struktur: edit di sites-available, symlink ke sites-enabled, jangan edit di enabled
- WAJIB: nginx -t SEBELUM reload. Salah 1 titik koma bisa bikin semua site down
- Reload bukan restart: reload = gak putus koneksi, restart = putus
- App Node harus listen 0.0.0.0:3000 bukan 127.0.0.1 kalau di-docker, tapi proxy_pass tetep ke 127.0.0.1:3000 kalau nginx di host
- Selalu set proxy_set_header Host, X-Real-IP, X-Forwarded-For, X-Forwarded-Proto biar IP asli kebaca di app
- SSL pakai certbot --nginx, jangan manual copy cert. Auto renew udah jalan di timer systemd
- Log: access_log & error_log per site biar gampang debug, jangan campur semua di default

4. DOCKER - JANGAN PAKAI :LATEST DI PROD
- Selalu pakai --restart unless-stopped di server, biar pas reboot auto nyala
- Jangan pakai :latest di prod, pakai tag versi: node:20-alpine, bukan node:latest
- Pakai .dockerignore: node_modules, .git, .env.local biar build 10x lebih cepet
- Volume: /app/node_modules harus di-anonimkan biar gak ke-overwrite sama mount host: -v .:/app -v /app/node_modules
- Log docker bisa bikin disk penuh: set di /etc/docker/daemon.json: "log-opts": {"max-size":"10m","max-file":"3"}
- Bersih2 rutin: docker system df, docker system prune -f (jangan -a --volumes di prod tanpa cek)
- 1 container 1 proses, jangan install nginx + app + mysql dalam 1 container

5. NETWORK - DEBUG URUT DARI BAWAH
- Urutan debug sakti: ip a (IP ada?) -> ip r (gateway?) -> ping 8.8.8.8 (internet?) -> dig google.com (DNS?) -> ss -tulpn (app listen?) -> ufw status (firewall?) -> curl -v 127.0.0.1:port
- ss -tulpn itu kunci kerajaan, hafal ini dulu baru netstat
- UFW: allow 22/tcp DULU sebelum enable, kalau enggak ke-lock SSH gak bisa balik. netplan try buat test config network baru
- App yang gak bisa diakses dari luar: cek dulu listen 0.0.0.0 atau 127.0.0.1 pakai ss -tulpn | grep 3000
- Jangan buka port DB (5432, 3306, 6379) ke public, bind ke 127.0.0.1 atau pakai docker network internal

6. FILE & TEXT & GREP - PIPE ITU SENJATA
- Jangan cat file 2GB, pakai less, head, tail -f. cat | grep itu useless cat, langsung grep file.log
- Selalu pakai grep -Rin (Recursive, ignore case, line number) buat cari di folder
- Kalau folder gede (node_modules), pakai rg (ripgrep) 10x lebih cepet, auto ignore .git
- Sed in-place: SELALU pakai -i.bak bukan -i, biar ada backup kalau salah ganti: sed -i.bak 's/old/new/g'
- Ganti path jangan pakai / sebagai delimiter: sed 's|/var/www/old|/var/www/new|g'
- Cek CRLF Windows (^M) pakai cat -A, bersihin pakai sed 's/\r$//' atau dos2unix
- Pipe pattern wajib: grep | cut | sort | uniq -c | sort -nr | head

7. DEPLOY - CHECKLIST BIAR GAK LUPA
- Sebelum deploy: git status, git pull, du -sh, df -h, docker system df (cek disk)
- Backup: cp .env .env.bak.$(date +%F), cp nginx.conf nginx.conf.bak
- Build: docker compose up -d --build atau npm ci --production
- Test: ss -tulpn | grep 3000, curl -v http://127.0.0.1:3000/health, nginx -t
- Reload: sudo systemctl reload nginx ATAU docker logs -f api --tail 50
- Monitor: journalctl -u app -f atau docker logs -f api, tail -f /var/log/nginx/error.log
- Rollback: kalau error, docker compose down && docker compose up -d previous_tag atau systemctl restart app

8. SECURITY & BACKUP - YANG SERING DISEPELEIN
- Update mingguan: sudo apt update && sudo apt upgrade -y, reboot kalau kernel update
- Fail2ban buat SSH: sudo apt install fail2ban -y, auto block IP brute force
- Backup 3-2-1: 3 copy, 2 media beda, 1 offsite (rclone ke gdrive)
- .env jangan pernah masuk git: echo ".env" >> .gitignore, chmod 600 .env
- Log rotate: cek /etc/logrotate.d/, jangan biarin /var/log/nginx/*.log jadi 20GB
- Umask 022 default, 027 buat server tim, 077 buat super sensitif

9. GIT & DOTFILES
- Semua config di ~/dotfiles, symlink ke ~/.bashrc ~/.config/nvim, push ke git private
- Commit message jelas: feat:, fix:, chore: biar gampang rollback
- Jangan commit secret, pakai git-secrets atau cek pakai: grep -R "AKIA\|sk_live\|password" --include="*.js" .

10. KEBIASAAN HARIAN SENIOR
- Sebelum rm -rf: ls dulu, atau pakai trash-put, atau rm -i
- Sebelum edit file prod: cp file file.bak.$(date +%F_%H%M)
- Pakai tmux atau screen biar pas SSH putus proses gak mati
- Alias di ~/.bashrc: alias ll='ls -lah', alias gs='git status', alias dc='docker compose'
- Dokumentasi di ~/cheatsheet/ kayak yang kamu bikin ini, otak manusia lupa, catatan enggak
